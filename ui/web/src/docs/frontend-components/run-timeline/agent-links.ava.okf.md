# Agent view arrows

The page reads `GET /api/insights/run-timeline/links` for the agents in view over the extent they span together ([[services/derived/insights/run_timeline/docs/run_timeline_links.ava.okf.md]]). `model/timeline-links.ts` (pure) resolves each event into two ends; `canvas/run-timeline-links-canvas.tsx` draws them on one canvas over the whole chart (`pointer-events: none`, redrawn per frame; row positions are read from the DOM); the existing row canvases are untouched.

- **One look.** An arrow is a C-shaped cubic Bezier: both control points sit level with their end and are pushed to the right (later in time) by 45% of the vertical distance (28-140 px, so a straight-down link still bends), whether the link goes up or down, so all arrows lean the same way. A per-link factor of 0.76-1.24 (a hash of its key) changes only the size of the bend, so simultaneous links do not coincide. The arrowhead follows the curve's end tangent; hit testing measures the distance to the sampled curve. A kind is told apart by color only (message blue, spawn green, fork teal, terminate red, restart amber, resurrect purple, notice pink; a message from the user keeps the message color). The legend under the chart lists the kinds with their count and switches each on or off.
- **Details.** A selected arrow shows a small header (kind, from and to, time, source, the add-agent button) and then the message through the one path every details panel uses: when the arrow ends on a block, that block's `TimelineMessages` (the same card and conversation row as the selected block's details); when it ends on none (a spawn, a notice, a message whose history carries no stamp, a peer outside the view) the preview the event carries goes through the same card and row (`PreviewMessage`). There is no text or Markdown rendering of its own.
- **Interactions switch.** A toolbar checkbox next to Context size, on by default, with two sub-switches, User and Other agents (on by default, greyed out while Interactions is off, and keeping their state when it comes back like the per-kind switches). Interactions off: no arrows, no link legend, no User or Other agents group (so the arrow keys never reach them) and no links read. A sub-switch off hides its group and every arrow with an end in it; arrows between agents in view answer only to Interactions and the per-kind switches.
- **Ends.** Both ends of an in-view agent are in its Messages row; there is no lifecycle row. The sender stands at the event's time; the block it was working on is not guessed. The receiver is the block of the inbound row the event was delivered as (a chat message, and terminate, restart, resurrect or fork when their row is stamped on a block), matched by `inbound_id`; with no such block it is the event's time. When the event names an inbound row but no block carries it (a history from before the checkpoint stamped `ava_inbound_id`, or a note block), the details say the arrow is not matched to a block. An end outside the visible range is not drawn. Events of the user or the system are not drawn.
- **Other agents.** A fixed group below the agents (and below User), with a heading and one row of events, no tree, Messages or Context rows. An event with one end in the view and the other an agent not in it lands on this row at its time, as a colored tick; its arrow joins the in-view end. Adding the peer (a button in the event's details) moves the arrow into that agent's own group. The group cannot be removed.
- **User.** The same kind of group, above Other agents, for the user (not an agent). Arrows: the user's chat messages (an inbound block whose source is `user` or `ui:page:*`, read from the receiver's units because a user chat has no audit event; the arrow starts at the block's read time and ends on the block, whose details show the source); audit events whose source is the user (spawn, terminate, restart, resurrect...); and notices an agent posted to the user (`agent_notices`, the only structured agent-to-user channel; its arrow runs from the agent to the User row). Every source of a person is merged into this one row, the details name which. Text an agent writes is not taken as a message to the user: no event says it is one. Arrow keys: down from the last agent enters the first non-empty group at the event nearest in time, left / right walk the group, down goes on to the next group, up back.
