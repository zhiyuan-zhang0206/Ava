# Agent view arrows

The page reads `GET /api/insights/run-timeline/links` for the agents in view over the extent they span together ([[services/derived/insights/run_timeline/docs/run_timeline_links.ava.okf.md]]). `model/timeline-links.ts` (pure) resolves each event into two ends; `canvas/run-timeline-links-canvas.tsx` draws them on one canvas over the whole chart (`pointer-events: none`, redrawn per frame; row positions are read from the DOM); the existing row canvases are untouched.

- **One look.** An arrow is a C-shaped cubic Bezier: both control points sit level with their end and are pushed to the right (later in time) by 45% of the vertical distance (24-60 px, so a straight-down link still bends), whether the link goes up or down, so all arrows lean the same way. A per-link factor of 0.76-1.24 (a hash of its key) changes only the size of the bend, so simultaneous links do not coincide. The arrowhead follows the curve's end tangent; hit testing measures the distance to the sampled curve. A kind is told apart by color only (message blue, spawn green, fork teal, terminate red, restart amber, resurrect purple, notice pink; a chat message of the user is its own kind, "User message", brown, with its own legend entry, count and switch, and "Message" counts only messages between agents). The legend under the chart lists the kinds with their count and switches each on or off.
- **Details.** A selected arrow shows a small header (kind, from and to, time, source, the add-agent button) and then the message through the one path every details panel uses: when the arrow ends on a block, that block's `TimelineMessages` (the same card and conversation row as the selected block's details); when it ends on none (a notice, a message whose history carries no stamp, a peer outside the view) the full text of the one selected event is read on demand (`/run-timeline/link-content`; the list carries no text, so its size does not grow with message length) and goes through the same card and row (`PreviewMessage`), long text folded by the row as anywhere; a notice also shows its title. A spawn, fork, terminate, restart or resurrect with no block has no text to show. There is no text or Markdown rendering of its own.
- **Merging.** The panel shows at most 20 arrows at once (the toolbar's "Max arrows" number box, default 20: a whole number from 1 to 500 takes effect at once; anything else, even empty, changes nothing, marks the box red and says what is accepted, the last valid number staying in force). When more are in view, arrows of one kind between the same two rows merge (`clusterToMax`): a binary search on the screen distance finds the smallest one at which the merged count is within the limit, so zooming in (fewer arrows in view) shrinks the distance and pulls them apart. A row is an agent's Messages row, or the User / Other agents group row (shared by every peer in it, so arrows to different outside agents can merge). Arrows of different kinds or rows are never merged: if the buckets alone outnumber the limit the result is the full merge and stays above it. The merged arrow stands at the mean of its members' ends, has the same width as any other and a count badge a fifth of the way along it, just after it leaves its start row and clear of the rows between (none for one). The result is cached by the arrows' positions, so hovering and selecting repaint without searching again; 20000 arrows search in about 15 ms. Hover reads `kind · #A → #B · N merged · first – last` (the row's name when the peers differ); a click selects every member and the details list them (time, ends); choosing one selects that link alone and zooms to a window 20 times the span the group covered. The legend counts links, not arrows. The limit was chosen from screenshots of the preview data zoomed out, at 20, 30 and 50; 20 was the only one that still showed structure.
- **Switches.** There is no master switch. The toolbar has "User interactions" and "Other agents interactions" (both on by default): one hides its group, the arrows that end in it and, with the group, the arrow keys' way to it; arrows between agents in view answer only to the per-kind switches of the legend. Each group's heading has a × like an agent's: it sets the same state as the toolbar switch (one state, the switch brings the group back), and closing the group of the selected arrow clears the selection.
- **Details.** A selected arrow shows a small header (kind, from and to, time, source, the add-agent button) and then the message through the one path every details panel uses: when the arrow ends on a block, that block's `TimelineMessages` (the same card and conversation row as the selected block's details); when it ends on none (a notice, a message whose history carries no stamp, a peer outside the view) the full text of the one selected event is read on demand (`/run-timeline/link-content`; the list carries no text, so its size does not grow with message length) and goes through the same card and row (`PreviewMessage`), long text folded by the row as anywhere; a notice also shows its title. A spawn, fork, terminate, restart or resurrect with no block has no text to show. There is no text or Markdown rendering of its own.
- **Ends.** Both ends of an in-view agent are in its Messages row; there is no lifecycle row. The sender stands at the event's time; the block it was working on is not guessed. The receiver is the block of the inbound row the event was delivered as (a chat message, and terminate, restart, resurrect or fork when their row is stamped on a block), matched by `inbound_id`; with no such block it is the event's time. When the event names an inbound row but no block carries it (a history from before the checkpoint stamped `ava_inbound_id`, or a note block), the details say the arrow is not matched to a block. An end outside the visible range is not drawn. Events of the user or the system are not drawn.
- **Other agents.** A fixed group below the agents (and below User), with a heading and one row of events, no tree, Messages or Context rows. An event with one end in the view and the other an agent not in it lands on this row at its time, as a colored tick; its arrow joins the in-view end. Adding the peer (a button in the event's details) moves the arrow into that agent's own group. The group cannot be removed.
- **User.** The same kind of group, above Other agents, for the user (not an agent). Arrows: the user's chat messages (an inbound block whose source is `user` or `ui:page:*`, read from the receiver's units because a user chat has no audit event; the arrow starts at the block's read time and ends on the block, whose details show the source); audit events whose source is the user (spawn, terminate, restart, resurrect...); and notices an agent posted to the user (`agent_notices`, the only structured agent-to-user channel; its arrow runs from the agent to the User row). Every source of a person is merged into this one row, the details name which. Text an agent writes is not taken as a message to the user: no event says it is one. Arrow keys: down from the last agent enters the first non-empty group at the event nearest in time, left / right walk the group, down goes on to the next group, up back.
