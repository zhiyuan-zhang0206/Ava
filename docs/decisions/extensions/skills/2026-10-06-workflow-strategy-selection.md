# Workflow chooses the working strategy

We chose a lightweight workflow entry that selects understanding, intent
alignment, goal definition, continuation, collaboration, and verification
independently. The user approved this direction after comparing persistent peers
and CodeAct with dedicated goal and script-orchestration features.

A fixed phase pipeline and a menu requiring users to understand internal feature
names were rejected. Neither task size nor parallelizability alone requires an
interview, a document, supervision, or delegation. Agents recommend concrete
trade-offs and choose routine methods within existing authorization; users may
explicitly select methods or leave selection to the agent.

Goal definition and sustained supervision remain separate choices. Dynamic
Workflow means executable orchestration code. Worker, supervisor, reviewer, and
orchestrator remain roles of the same persistent peer mechanism. This change
introduces no new agent type, workflow registry, scheduler, or budget controller.
Budget and authority commitments continue to govern every selected method.

The current procedure is owned by
