# Historical choices

These records explain choices, rejected alternatives and trade-offs at the time
of the decision. Their dates and technical evidence are preserved. A record can
be superseded by later code or a later decision; it is not a current contributor
workflow requirement. Follow [the contribution guide](../contributing.md),
[current conventions](../conventions/README.md) and the relevant component's
local `docs/` for today's contract.

When a choice changes, add a new dated decision and link the supersession; do not
rewrite the earlier reasoning to match current behavior.
