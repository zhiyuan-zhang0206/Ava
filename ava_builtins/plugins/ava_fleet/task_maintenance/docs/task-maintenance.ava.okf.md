# Task-Maintenance — Task Reminders + Escalation

## What It Is
A gateway-owned daemon — every Fleet `task_maintenance_interval_seconds` (default 5 min) scans `agent_tasks`, chat-reminds owners of in-progress tasks overdue for updates, and escalates repeat non-responders: with a delegator (parent task has an owner) notify the parent owner; top-level tasks (parent = unowned system root) escalate to the human queue via a require_response notice on the stuck owner. Cluster-level, one per cluster, same shape as heartbeat. **Only sends messages / inserts notices, never modifies task status**—no stale sweep, no auto-cancel, no orphan release.

**Attribution**: fleet domain service under the `ava_fleet` plugin namespace (not hardcoded in core `ops/spec.py`): the plugin declares a `ServiceSpec` via `ava_builtins/plugins/ava_fleet/services.py:services()`, `ops/spec.py:plugin_services()` discovers it into the single-source `build_services()` roster—"plugin declares, ops discovers"; gateway capability. **Discovery keys on the plugin code's existence, not the agent-side enable-state**; the host gate is Fleet image field `task_maintenance_enabled` (via `ServiceSpec.gate`, evaluated at daemon-start, unaffected by per-agent overlays).

## Core Responsibilities
- **Remind**: SELECT `status='in_progress' AND owner IS NOT NULL AND NOT is_root` and `now()-updated_at > remind_interval_seconds`, `ORDER BY priority, id` (P0 first); deliver one per-owner digest through a direct `inbound_messages` INSERT (`kind='system_note'`, `source='system'`), publish an owner invalidation hint after commit, then best-effort Redis-wake it. The digest copy is imperative (user ruling 2026-08-29): each line orders the owner to report current status and advance the next step, and to state why and raise `remind_interval_seconds` when it cannot advance — an explicit wait instead of silent idling. The selected task rows are locked with `FOR UPDATE SKIP LOCKED`; digest insertion and `last_reminded_at=now()` / `reminder_count += 1` commit in the same transaction. Concurrent sweeps cannot accept the same cadence twice. A rollback preserves both queue and counters; a crash after commit leaves the pending digest recoverable by the existing inbound wake scan. Post-commit hint failure cannot re-arm that cadence. After commit, and telemetry records `task_reminder_digest`. `last_reminded_at` gates the backoff (`AVA_TASK_REMINDER_BACKOFF_SECONDS`, default 3600s)—at most one reminder per backoff within the same overdue window (so the count can climb to the escalate threshold in one window).
- **Escalate**: fires when `reminder_count` reaches `AVA_TASK_ESCALATE_N` (default 3). Two paths: **with delegator** (parent owner non-null) → per-owner digest chat to the parent owner; **without delegator** → INSERT a require_response `agent_notices` on the stuck owner (`task_id`=that task, `priority` inherited, "stuck, please reassign or cancel"). The notice is attached to the agent but **audience is human**—the notice read surface supplies its content to the human queue. The delegation path is **at most once per overdue window**: it fires at `>=` threshold while `escalated_at` is unset, and the delivered digest's own transaction stamps `escalated_at` (a failed delivery leaves it unset and the next sweep retries; any update() clears it with the reminder counters, re-arming the next window). The user path uses `>=` (an already-open notice **skips the round and retries next sweep**, so slipping past the threshold never permanently misses the window), and the sent notice itself is the idempotency marker, keeping "at most one open notice per agent". Candidate discovery does not authorize delivery: each batch locks current tasks and their discovered parents in stable id order with `FOR NO KEY UPDATE SKIP LOCKED`, then rechecks the task window and current parent owner. Locked or newly reparented tasks defer to a later sweep. The weaker row lock still fences mutations but allows gateway notice creation to take its task foreign-key key-share lock while holding the agent identity lock. All recipient identities are locked in stable id order; human notice open checks and local-id allocation share the gateway creator's physical `agents` lock. Digest insertion and escalation markers commit together in one batch transaction; a failure rolls the entire batch back. Live hints and `task_escalation` telemetry follow commit. Resolving a human notice still permits a later sweep to re-alert.
- **No resurrection for terminated owners**: direct delivery leaves their system `inbound_messages` rows unclaimed and only attempts the best-effort Redis wake; it never resurrects the terminated owner. The task instead escalates for reassignment or cancellation (2026-08-22 user ruling).
- **Schema drift suicide**: `psycopg.ProgrammingError` (code↔DB drift) directly exits, relying on healthcheck to restart, not retrying to mask the issue.
