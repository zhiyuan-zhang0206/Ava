# Agent-Ops — Strongly-Typed Wire Layer

Request/response are no longer hand-assembled dicts — `OpEnvelope` (`{kind: str, payload: dict}`) in, `OpResponse` (`{status: "completed"|"failed", result: dict}`) out, with the legal set of `kind` being the `OpKind` Literal (re-exported from here by `ops/cluster_rpc.py` to keep old importers working). Each kind has dedicated pydantic payload/result models (e.g., `LifecyclePayload`, `ClusterUpdatePayload`, `ConfigWritePayload`, `InventoryWritePayload`, `AgentSkillViewPayload`; `ConfigReadResult`, `ConfigWriteOpResult`, `InventoryReadResult`, `InventoryWriteOpResult`, `ClusterSpawnSession`, `AgentSkillViewResult`). Pending-work resurrection carries `LifecyclePayload.trigger_inbound_id` plus `trigger_inbound_kind` (`chat` or `compact_request`) only on the distinct `resurrect-if-pending-work-v2` path; explicit manual resurrection uses `resurrect-explicit-v2`; the delivery watchdog's stalled crash-marked harvest uses `recover-crash-marked-v2` (adjudicated by `ops/ops_lifecycle.py::recover_crash_marked_op`); the billing batch-recovery entry dispatches its per-agent rescue as `resurrect-billing-v1` (task #3919). A version-skewed old runner rejects the unknown versioned paths, while a new runner rejects legacy `/resurrect`, so neither rollout direction silently drops the guard and resurrects unconditionally. The daemon's `_dispatch` (`services/agent_ops/daemon.py:_dispatch`) uses `match kind:` to branch, validate the payload (`cluster_prepare_facts` / `cluster_prepare_dispatch` in JSON mode), call the corresponding `ops/ops_*.py` function, and `.model_dump(mode="json")` serialize the result — unknown kind falls to `case _` returning `failed`, not a crash. A managed-writer dispatch (`cluster_prepare_dispatch`, task #4129) is a no-effect kind: the unit seals the plan locally and answers with its validation acknowledgement, where a refusal is data (the acknowledgement's `refusal` field) rather than an op failure. Failure state is unified as `OpFailure` (`error`/`detail`/`reason`), where `reason` is an enum value of `AvaAgentError`, allowing the gateway side to reconstruct the original exception. This batch of schemas is a bidirectional contract between gateway↔agent-runner, so placed in the `ops` layer following import layering (`shared < ops < gateway`) — gateway imports downward, `ops`/`services` never reach upward into gateway.
