# Run Timeline Reads

Served by [[services/derived/insights/docs/insights.ava.okf.md|the insights service]]; the gateway proxies these URLs.

`GET /api/agents/{id}/run-timeline?from&to` serves a window over the two things an agent persists about its own run: its message history and its understanding tree (`understanding_nodes`). Nothing is read from Loki.

- **Window.** Without `from`/`to` it is the agent's whole lifetime: the earliest message or node to the latest (read times) (`lifetime` in the response). Audit events and inbound rows never move it. An agent with neither falls back to the last 24 hours and `lifetime: null`. Drilling is asking for a node's or unit's span as the window.
- **`nodes`.** Every tree level intersecting the window (on read times), none capped; only nodes of this pipeline (`chunk-*` / `group-*` engine versions: a bare-number node an older release's worker wrote in a mixed-version window is not read). `level` is the engine level (1 = leaves), stable across windows. Each node carries `span_start..span_end` (stitched message indices), its full `summary`, `usage` (the AIMessage `usage_metadata` summed over the span: calls, input, cache read, cache write, output; plus `cost_usd`, the sum of the `ava_usage.cost_usd` the AIMessages recorded, over the `cost_calls` of the `calls` that carry one — a call without it, older or unpriced, is unknown and never estimated; `hierarchy/usage.py`) and `generation` (calls, tokens and seconds of the understanding calls that wrote it: a node records its chunk `job_id` or its grouping `check_key`, the cost is that job's or check's, shared by the groups it wrote; None for a node written before the link existed). A node whose span lies past the history (an orphan) is left out with a warning, not a 500.
- **Times are read times.** A message's time is when the model read it, never before the message before it. A message's own time is `message_read_time` (`ava_picked_up_at` when it records the pickup); an older message has only `ava_created_at`, its arrival, which can be earlier than its predecessor's (an inbound message stamped on arrival while the agent was still streaming) and would overlap neighbours on the axis, so its read time is rebuilt as the latest arrival so far in message order (`units.read_times`). Every time served (unit, node, window, lifetime) is a read time, and a node sits on the extent of the layer-0 blocks it covers (`serve_nodes`): it starts where the earliest block opening at its first message starts (a turn's thinking block begins at the read time of the message before it) and ends where the latest block closing at its last message ends, so contiguous nodes of a level abut exactly and a parent spans exactly its children. A message that opens or closes no block falls back to its read time. What stays blank between nodes of one level is real: a compaction segment's head (its messages belong to no node) and the not yet summarized tail of the level below. Data that records the pickup passes through unchanged; older data gets its read order back here. The stored node `start_ts` / `end_ts` and the raw message stamps are not rewritten and not served (the raw message detail keeps its own `ava_created_at`).
- **`units`.** Layer 0 as the timeline draws it: the deterministic message units of `hierarchy/units.py` (inbound, text, note) with each work unit split into three blocks by `display_blocks`: `thinking` (the model's generation for the turn, from the read time of the previous message to the end of the stream; when the turn also has text and a recorded reasoning time `ava_reasoning_ms_by_block`, it ends after that time and the `text` block takes the rest of the stream), `call` (an instant at the end of the stream) and `output` (from the end of the stream to the tool result). A turn of only text spans its stream. Each block carries its own `kind`, extent, the message span of its unit (`i0`..`i1`) and a preview, and `parent`: the id of the level-1 node whose span holds the block's first message (None when no node covers it); the page lights a selection's chain of ancestors from it. Grouping and the catalog are not affected: a work unit stays one unit there. Blocks overlapping the window and carrying a read time are served.
- **Context per block.** Each unit also carries what the Context size row draws (`tokens.BlockContexts`): `context_total`, the context through the block (its session's head and everything up to and including it, each message at the weight it was read with; None while no request has read it), `session` (zero-based compaction segment; the total starts over in each) and `request`, the usage of the LLM request its AIMessage was (input, output, cache, cost), repeated on each of the message's turn blocks, None on any other block. The blocks of one AIMessage (thinking, text, call, in time order) each add their share of the message (`ai_message_parts`, the split their own `context_tokens` use), so the first starts from the `input_tokens` of the request that produced the message and the last ends at the context through the whole message; a message block (inbound, note, output) is the context through its last message. The page draws the Messages row and the Context size row from the same units, so the two rows hold the same blocks.
- **`inbound_id`.** An inbound or note unit has `inbound_id`, its `inbound_messages` row (the message's `ava_inbound_id`, none on older histories) ([[run_timeline_links.ava.okf.md|the links read]] matches on it).

Each unit carries `context_tokens` / `generation_tokens` / `estimated` (`tokens.py`): a message block sums its messages' counts (None while no request has read it); a thinking / text / call block is its share of the turn's AIMessage by the estimator, so estimated unless the message has one part. Each request carries the provider's `input_tokens` and `output_tokens`.

`GET /api/agents/{id}/run-timeline/messages?start&end&limit&full` returns raw messages by stitched index (at most `limit`, `next_start` continues), split into parts by the console timeline's projection; parts longer than `display.run_timeline_message_text_max` are clipped and flagged unless `full=true`; a message carries `context_tokens` / `estimated` (None until a request reads it).

`GET /api/agents/{id}/run-timeline/context?at=` (`context.py`, `llm_requests`) returns the context breakdown of the LLM request at message index `at` (the first request at or after it, else the last; 404 when the agent has made none): the same `ContextBreakdownResponse` the composer's `context-breakdown` returns (shared `base.agents.history.context_response.context_breakdown_response`: window, thresholds), computed over what that request really sent (the segment's own head, then the segment's messages before the request's AIMessage) from each message's own token count (`base/agents/history/message_tokens.py`, `request_breakdown`; the categories sum to the request's `input_tokens`), each category carrying `estimated` / `exact_fraction`, plus `request`, `session` / `sessions` (zero-based session of the count) and `ts`. It works for any session of the stitched history, not only the latest.

One `TimelineReadInputs` supplies cached derivation and raw rendering with live policy readers.

`HistoryViewCache` (`history.py`, on `app.state.run_timeline_views`) keeps up to 16 agents' derived views (history, units, usage sums, per-message token counts; about 12 KB per message) keyed by agent id: served as is for 5 seconds, then kept for up to 10 minutes while the agent's newest checkpoint id is unchanged (one cheap probe), rebuilt when it moves; concurrent readers of one agent share a single build; a read that finds a node past the cached history asks for a fresh view. A node span outside the history is an explicit error.
