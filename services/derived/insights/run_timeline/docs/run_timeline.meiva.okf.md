# Run Timeline Reads

The gateway proxies [[services/derived/insights/docs/insights.meiva.okf.md|Insights]].

`GET /api/agents/{id}/run-timeline?from&to` serves a window over message history and the understanding tree (`understanding_nodes`). It does not read Loki.

- **Window.** Without `from`/`to` it is the agent's whole lifetime: the earliest message or node to the latest (read times) (`lifetime` in the response). Audit events and inbound rows never move it. An agent with neither falls back to the last 24 hours and `lifetime: null`. `recent_hours=24` selects the last day ending at the last recorded activity (clipped to the lifetime), not the current wall clock; it cannot be combined with `from`/`to`. The page starts there and requests explicit time windows when panned or zoomed.
- **`nodes`.** Every tree level intersecting the window (on read times), none capped. `level` is the engine level (1 = leaves), stable across windows. Each node carries `span_start..span_end` (stitched message indices), its full `summary`, `usage` (the AIMessage `usage_metadata` summed over the span: calls, input, cache read, cache write, output; plus `cost_usd`, the sum of the `meiva_usage.cost_usd` the AIMessages recorded, over the `cost_calls` of the `calls` that carry one — a call without it, older or unpriced, is unknown and never estimated; `hierarchy/usage.py`) and `generation` (calls, tokens and seconds of the understanding calls that wrote it: a node records its chunk `job_id` or its grouping `check_key`, the cost is that job's or check's, shared by the groups it wrote; None for a node written before the link existed). A node whose span lies past the history (an orphan) is excluded by the message-count bound, not a 500.
- **Times are read times.** A message's time is when the model read it, never before the message before it. A message's own time is `message_read_time` (`meiva_picked_up_at` when it records the pickup); an older message has only `meiva_created_at`, its arrival, which can be earlier than its predecessor's (an inbound message stamped on arrival while the agent was still streaming) and would overlap neighbours on the axis, so its read time is rebuilt as the latest arrival so far in message order (`units.read_times`). Every time served (unit, node, window, lifetime) is a read time, and a node sits on the extent of the layer-0 blocks it covers (`projection/nodes.py`): it starts where the earliest block opening at its first message starts (a turn's thinking block begins at the read time of the message before it) and ends where the latest block closing at its last message ends, so contiguous nodes of a level abut exactly and a parent spans exactly its children. A message that opens or closes no block falls back to its read time. What stays blank between nodes of one level is real: a compaction segment's head (its messages belong to no node) and the not yet summarized tail of the level below. Data that records the pickup passes through unchanged; older data gets its read order back here. The stored node `start_ts` / `end_ts` and the raw message stamps are not rewritten and not served (the raw message detail keeps its own `meiva_created_at`).
- **`units`.** Layer 0 as the timeline draws it: the deterministic message units of `hierarchy/units.py` (inbound, text, note) with each work unit split into three blocks by `display_blocks`: `thinking` (the model's generation for the turn, from the read time of the previous message to the end of the stream; when the turn also has text and a recorded reasoning time `meiva_reasoning_ms_by_block`, it ends after that time and the `text` block takes the rest of the stream), `call` (an instant at the end of the stream) and `output` (from the end of the stream to the tool result). A turn of only text spans its stream. Each block carries its own `kind`, extent, the message span of its unit (`i0`..`i1`) and a preview, and `parent`: the id of the level-1 node whose span holds the block's first message (None when no node covers it); the page lights a selection's chain of ancestors from it. Grouping and the catalog are not affected: a work unit stays one unit there. Blocks overlapping the window and carrying a read time are served. The page sends `max_units=5000`: if the window exceeds that count, `units` is empty and `units_omitted` is the exact count. Dense windows count historical blocks without fetching their payloads; the page asks the user to zoom in. Nodes remain available. Unbounded callers retain the original full-detail contract.
- **Context per block.** Each unit also carries what the Context size row draws (`tokens.BlockContexts`): `context_total`, the context through the block (its session's head and everything up to and including it, each message at the weight it was read with; None while no request has read it), `session` (zero-based compaction segment; the total starts over in each) and `request`, the usage of the LLM request its AIMessage was (input, output, cache, cost), repeated on each of the message's turn blocks, None on any other block. The blocks of one AIMessage (thinking, text, call, in time order) each add their share of the message (`ai_message_parts`, the split their own `context_tokens` use), so the first starts from the `input_tokens` of the request that produced the message and the last ends at the context through the whole message; a message block (inbound, note, output) is the context through its last message. The page draws the Messages row and the Context size row from the same units, so the two rows hold the same blocks.
- **`inbound_id`.** An inbound or note unit has `inbound_id`, its `inbound_messages` row (the message's `meiva_inbound_id`, none on older histories) ([[run_timeline_links.meiva.okf.md|the links read]] matches on it).

Each unit carries `context_tokens` / `generation_tokens` / `estimated` (`tokens.py`): a message block sums its messages' counts (None while no request has read it); a thinking / text / call block is its share of the turn's AIMessage by the estimator, so estimated unless the message has one part. Each request carries the provider's `input_tokens` and `output_tokens`. One derivation-owned `BlockContexts` reuses each AIMessage's context and generation splits for all its blocks and context totals; its cache ends with that segment derivation.

`GET /api/agents/{id}/run-timeline/messages?start&end&limit&full` returns raw messages by stitched index (at most `limit`, `next_start` continues), split into parts by the console timeline's projection; parts longer than `display.run_timeline_message_text_max` are clipped and flagged unless `full=true`; a message carries `context_tokens` / `estimated` (None until a request reads it).

`GET /api/agents/{id}/run-timeline/context?at=` (`projection/reader.py`) returns the context breakdown of the LLM request at message index `at` (the first request at or after it, else the last; 404 when the agent has made none): the same `ContextBreakdownResponse` the composer's `context-breakdown` returns (shared `base.agents.history.context_response.context_breakdown_response`: window, thresholds), computed over what that request really sent (the segment's own head, then the segment's messages before the request's AIMessage) from each message's own token count (`base/agents/history/message_tokens.py`, `request_breakdown`; the categories sum to the request's `input_tokens`), each category carrying `estimated` / `exact_fraction`, plus `request`, `session` / `sessions` (zero-based session of the count) and `ts`. It works for any session of the stitched history, not only the latest.

`TimelineReadInputs` supplies live policy readers to derivation and raw rendering.
