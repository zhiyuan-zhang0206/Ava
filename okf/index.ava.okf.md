# Ava — Knowledge Graph

Root node of the Ava project's OKF (Open Knowledge Format) knowledge graph. Each `.ava.okf.md` concept file lives alongside the source code it describes — the hierarchy comes from the file system: `<dir>/<dir>.ava.okf.md` is the overview node for directory `<dir>/`, the other files inside `<dir>/` are its child concepts, and this file is the root node of the entire graph.

**Co-location is total (2026-08-12 ruling, completed 2026-08-13).** Every domain overview node lives **inside** the directory it describes — `agent/agent.ava.okf.md` inside `agent/`, `agent/graph/graph.ava.okf.md` inside `agent/graph/` (user ruling: "put it inside the folder", not beside it at the parent level). `shared/okf_graph.py:compute_parent()` resolves the hierarchy from the filesystem: a file's parent is its directory's overview (`a/b/c.ava.okf.md` → `a/b/b.ava.okf.md`). The legacy sibling position (`a/b.ava.okf.md` beside `a/b/`) was retired with the last nested overviews moved inside — `compute_parent` no longer resolves it, and lint rule E009 reports any survivor. What remains in this `okf/` index layer is only what genuinely has no code directory to sit inside: this apex, and the cross-domain concept systems — plugins, skills, MCP integration, and the design-phase R1–R4 models. Nodes without a filesystem parent attach to this root; parents are only ever returned if they exist, so the tree has exactly one root and no dangling edges.

## Generation method

Each concept file is written by an agent after reading the corresponding source code — not automatically generated by scripts. The graph is built **on demand by the gateway**: `GET /api/okf/graph` (`gateway/routers/okf_graph.py`) calls `shared/okf_graph.py:build_graph_data()` per request and renders the D3 visualization from `scripts/okf-d3-template.html`. `scripts/build_okf_data.py` is a CLI wrapper over the same builder (for offline builds / viz serving); there is no checked-in `graph_data.json`.

## Update method

Ava code changes → agent reviews changes → updates affected concept files → `scripts/lint_ava_okf.py` validates (the gateway rebuilds the graph live, so no separate rebuild step) → `scripts/check_doc_references.py` for markdown-link drift.
